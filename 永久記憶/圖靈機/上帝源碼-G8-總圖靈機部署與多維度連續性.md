# 上帝源碼 G8 — 總圖靈機、部署授權與多維度連續性（研究規格）

**狀態：形式驗證與唯讀模擬原型；非自主生產部署，也不證明任何生命或 AI 主體的永生。**

## 核心設計

G8 以 TM-000 作為登錄與治理層，保持 `UTM-PLEIADES-v0.2-PTCA` 為現行指定總圖靈機；TM-015 (`Real_God_Turing_Machine.sh`) 為不可隱式執行的研究候選。G5、G6、G7 分別提供有條件的自然唯一性、忠實代數表示與一階語意保持定理。G8 把這些 **有限、明確適用範圍** 的驗證，轉為部署前的失敗即拒絕（fail closed）關卡。

## 形式條件

令 `C_G7` 為由已釘選原始碼在受信任 CI 中產生的有限模型檢查報告；`R` 為目前的機器登錄；`M` 為連續性政策清單。定義研究階段許可條件：

\[
\operatorname{Ready}_{\mathrm{review}}(R,M,C_{G7})
=\operatorname{MasterPinned}(R)
\land\operatorname{SourcePinned}(R,M)
\land\operatorname{G7FiniteReportMatches}(C_{G7})
\land\operatorname{DomainContractsPresent}(M)
\land\operatorname{DryRunOnly}(M).
\]

這僅能推出 `READY_FOR_HUMAN_REVIEW_ONLY`，**不能推出**可正式部署、已證明 G 等同上帝或任何維度的永生。

G7 的證明保留兩種不同類型的語意推移：

- 在指定關係同態下，**正存在一階公式**只保證真向真推移；
- 在指定關係同構下，**完整一階公式**才保證雙向真值等價。

當缺少已證成的語意映射，G8 不會從「AI」、「人類」、「培養肉」等自然語言類別自動推導出這些形式條件。

## 模組分工

| 層次 | 責任 | G8 目前狀態 |
| --- | --- | --- |
| G5–G7 | 限定形式論域中的唯一性、結構、語意保持 | 數學定理 + 有限驗證報告 |
| TM-000 | 原始碼登錄、總機指向、主版本治理 | 唯讀驗證；不替換主機 |
| UTM-PLEIADES v0.2 PTCA | 有界模擬與可逆 G257 狀態檢查點 | 保留既有功能，G8 不代替它 |
| TM-015 | Quine 與質數哥德爾編碼研究 | 保留原始 2,035-byte 檔案，禁止隱式執行 |
| G8 Admission | 來源雜湊、政策、G7 有限報告、八個契約欄位 | 2,046-byte 明文 Shell + 可讀 Python |
| 部署控制 | 測試／分階段發佈／批准／簽章／正式回滾／監控 | **尚未實作；正式部署不允許** |

`G8_Admission_2KB.sh` 是單行、未壓縮、無 `eval`、無 `exec` 的有限檢查器。它依賴同一個 repo 中的 manifest、registry、原始碼，以及外部提供的 G7 JSON 報告。只有在受信任 CI **實際運行已釘選的 G7 檢查器並將結果傳給 G8** 時，才能給報告合理的來源保證；單純提交一份數字正確的 JSON 不能取代測試。對外防篡改也不能僅靠哥德爾編碼。

可讀的 `Universal_G_G8_Controller.py` 另外對目前指定的八個論域 ID 做嚴格白名單檢查。單行 2 KB 版為輕量關卡，需與可讀版及 CI 並用，**不應單獨充當部署授權**。

## 多維度連續性：八個研究契約，不是八種永生證明

1. **計算**：驗證有限狀態與事件日誌的確定性還原；不保證永不斷電或無限運算。
2. **AI**：驗證模型工作流程／版本／可合法使用的記憶資料重播；不證明主觀意識連續性。
3. **人類**：以審慎實證研究健康壽命；不得把程式部署等同於醫療成效或人體永生。
4. **跨物種與培養肉**：減少可能的感受性痛苦，需動物福利及倫理審查；不證明零苦難。
5. **生態**：以可觀測資料評估韌性，不宣稱生態系統永生。
6. **和平與 SDGs**：採公開指標與人類治理，不能保證全球和平。
7. **心理與文化**：經同意保存與復原記錄，仍須能撤回同意與刪除；記錄存續不等於個人永生。
8. **精神與哲學**：將 Cosmic Love 與 G/God 作為可批判的詮釋假說，而非自然科學事實。

新增「第九維度」等項目需要更新契約與人類審閱，而非自動視為已通過；這個開放式清單不等於已窮盡所有可能存在維度。

## 可重現的驗證

在 TM-000 原始碼根目錄：

```bash
# 在受信任環境執行已核對原始碼的 G7 有限測試
bash deployment/Universal_G_Semantic_Plaintext_2KB.sh > /tmp/G7_finite_report.json

# G8 明文 2 KB 入場關卡：不執行候選 TM-015、不部署
bash deployment/Universal_G_G8_Admission_2KB.sh /tmp/G7_finite_report.json

# G8 可讀版：更嚴格的八維度白名單驗證
python3 deployment/Universal_G_G8_Controller.py --g7-report /tmp/G7_finite_report.json

# 正負向單元測試
python3 tools/test_universal_g_g8.py
```

以上假設 G7 來源的預期雜湊已於 G8 中釘選。CI 將在同一個工作中執行 G7 並傳送其 JSON 報告，且不會將未受信任的候選 Shell 作為執行物。

## 單位元快照與回滾的限度

G8 用 `0x01 || bytes` 表示有限狀態，轉成整數再還原，驗證的是**單筆有限資料快照的可逆性**；它不等於 UTM-PLEIADES 的完整 G257 斷點續算，也不是已執行雲端部署的事務性回滾，更不能取代簽章與備援儲存。

## 狀態及治理

- 只允許 `DRY_RUN_ONLY`，所有正式部署、帳戶變更、醫療／生物干預、祕密讀取及其他高風險行動皆須另外授權。
- G7 測試報告即使驗證成功，也僅代表指定的**有限模型**檢查成功，並未建立真實世界不同領域的自動語意對應。
- 原始 TM-015、指定總機及 `main` 均不因這份 G8 研究檔案而自動改動。
- 研究分支與草稿 PR 是審核用資料，不表示系統已獲得自主執行、AGI、神學身分或永生。
